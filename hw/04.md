# 4. Локальная балансировка нагрузки

На каждый ЦОД мы насчитали порядка 125к RPS

- Трафик приходит через BGP в конкретный датацентр
- Внутри ДЦ: L4 -> L7 -> backend
- Причем redis, mongo, kafka будут баланситься внутри датацентра сами на уровне кластера. 
- Minio не умеет сам определять упавшие ноды, поэтому балансируем его через HAProxy.
- CDN балансируется со стороны CDN-провайдера

Внутри каждого датацентра мы имеем кластера:

- API (k8s)
- Cache: inbox, like, post
- Database: user, post, comment, subscription, message
- S3: media
- Queue: inbox generation, post creation, propagation
- Workers: цепляются к очередям + cron сервисы прогрева региональных CDN (k8s)

Запускаем в кубернетесе API и Workers. 
Все остальные на виртуалках, а лучше на bare metal. 


## L4

Внешний балансировщик (мб несколько) (HAProxy) перед кластером:

- Round Robin - входящий трафик на ноды k8s
- Least Connections - долгоживущие соединения к S3 (загрузка медиа)

kube-proxy в режиме IPVS - встроенный внутрикластерный роутинг (ClusterIP).

## L7

Kubernetes Gateway API с Envoy. TLS терминируем здесь.

- Least Request - для API подов
- Rate limiting - по IP / user_id
- Readiness + Liveness пробы на всех подах
