# 4. Локальная балансировка нагрузки

На каждый ЦОД мы насчитали порядка 125к RPS/

- Трафик приходит через BGP балансировку в конкретный датацентр
- локально внутри ДЦ трафик проходит через L4 -> L7 -> backend
- CDN локально балансируется со стороны CDN провайдера

Внутри каждого датацентра мы имеем кластера:

- API (k8s)
- Cache: inbox, like, post
- Database: user, post, comment, subscription, message
- S3: media
- Queue: inbox generation, post creation, propagation
- Workers: цепляются к очередям + cron сервисы прогрева региональных CDN (k8s)

Запускаем в кубернетесе API и Workers. 
Все остальные на виртуалках, а лучше на bare metal.

## L4

Используем kube-proxy с IPVS

- Least Connections - для долгоживущих соединений (S3).
- Round Robin - для коротких запросов (API).
- Consistent Hashing - для кешей (inbox)


## L7

Используем Kubernetes Gateway API с Envoy. Снимаем TLS

- Round Robin - для API
