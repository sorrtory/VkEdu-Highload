### 11.1.2 Нагрузка на один дата-центр

Проект разворачивается в 3 дата-центрах: `MSK`, `SBP`, `EKB`. По ДЗ 4 каждый ДЦ должен выдерживать половину общей нагрузки, чтобы система переживала потерю одного дата-центра.

## 11.2 Модель развёртывания

Stateless-микросервисы разворачиваются в Kubernetes. Stateful-компоненты и балансировщики разворачиваются на выделенных bare-metal серверах, потому что им важны диски, сеть, предсказуемая задержка и отсутствие накладных расходов контейнерной сети.

| Компонент                                       | Модель развёртывания | Обоснование                                           |
| ----------------------------------------------- | -------------------- | ----------------------------------------------------- |
| `api-gateway`, доменные сервисы, worker-сервисы | Kubernetes           | Stateless, удобно горизонтально масштабировать        |
| LVS                                             | Bare-metal           | L4-балансировка, высокая сетевая нагрузка             |
| Nginx                                           | Bare-metal           | TLS termination, L7 routing, высокая сетевая нагрузка |
| PostgreSQL                                      | Bare-metal           | Stateful, строгая консистентность, Patroni            |
| ScyllaDB                                        | Bare-metal           | Stateful, высокая запись/чтение, локальные NVMe       |
| Redis                                           | Bare-metal           | In-memory cache, важна предсказуемость RAM            |
| Kafka                                           | Bare-metal           | Stateful broker, важны диски и сеть                   |
| OpenSearch                                      | Bare-metal           | Индексы поиска, локальные диски                       |
| SeaweedFS                                       | Bare-metal           | Объектное хранилище, большие HDD-пулы                 |
| CI/CD и временные окружения                     | Аренда               | Нагрузка нерегулярная, важна эластичность             |

Для файлового хранилища стартовый расчёт сделан под один год прироста: 11,56 ПБ логических данных. При `RF=3` нужно 34,68 ПБ raw. Один storage-capacity сервер даёт 96 ТБ raw, поэтому нужно `ceil(34 680 / 96) = 362` узла на проект, примерно 121 узел на ДЦ.

Если переносить полный исторический архив из ДЗ 5 на 400 ПБ логических данных, то потребуется `400 ПБ * 3 / 96 ТБ = 12 500` volume-узлов. Это уже отдельная программа миграции и закупки, а не стартовый парк.

## 11.5 Расчёт Kubernetes-узлов

В Kubernetes размещаются только stateless-сервисы.

| Параметр                        |             Значение |
| ------------------------------- | -------------------: |
| CPU requests stateless-сервисов |            224 cores |
| Kubernetes overhead             |                  20% |
| CPU с overhead                  |            269 cores |
| CPU на один kubenode            |             64 cores |
| Расчёт без резерва              | `ceil(269 / 64) = 5` |
| Резерв                          |               1 узел |
| **Итого на один ДЦ**            |       **6 kubenode** |
| **Итого на 3 ДЦ**               |      **18 kubenode** |

Выбранный Kubernetes-узел: 64-core bare-metal сервер с 256 ГБ RAM и NVMe. По CPU хватает 6 узлов на ДЦ. По RAM запас большой: `6 * 256 = 1536 ГБ`, requests stateless-сервисов составляют 448 ГБ.

## 11.9 Что покупать, что арендовать

Главная развилка: проект крупный, нагрузка стабильная и хорошо прогнозируемая. Поэтому почти весь production-парк выгоднее покупать. Аренда нужна там, где важна эластичность или нагрузка нерегулярная.

| ----------------------------- | ----------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------- |
| Kubernetes-узлы               | Покупать                                                          | 18 постоянно загруженных серверов         | Покупка 30,6 млн ₽ против аренды 75,2 млн ₽ за 5 лет     | Низкий: типовая конфигурация                         |
| LVS                           | Покупать                                                          | Постоянный edge-трафик, простые серверы   | Покупка дешевле аренды в 2,1 раза за 5 лет               | Низкий                                               |
| Nginx L7                      | Покупать                                                          | Постоянная TLS/L7 нагрузка                | Покупка 15,5 млн ₽ против аренды 40,3 млн ₽              | Низкий                                               |
| PostgreSQL                    | Покупать                                                          | Stateful, нужны NVMe и контроль latency   | Покупка 7,5 млн ₽ против аренды 19,1 млн ₽               | Средний: нужны DBA и backups                         |
