# 3. Глобальная балансировка нагрузки

> [Карта](https://yandex.ru/maps/?um=constructor%3Ab0018114f2724b8fe721d684c0e85e0514cc55cf5ba3de8b100922e54fb94bf5&source=constructorLink)
> ДЦ: Петербург, Москва, Екатеринбург
> CDN: Москва, Волгоград, Екатеринбург, Новосибирск, Хабаровск

На 1000 км идет задержка примерно 10 мс.
Мы работаем только по РФ и 70% пользователей находятся в ее европейской части.
Важно обеспечить быструю загрузку контента для европейской части России,
остальные регионы будут терпеть более высокий RTT.
Наше приложение не предполагает рилтайм, поэтому даже 10_000 км ~= 200 мс
RTT для получения поста в ленте не будет непреодолимой преградой.

## Домены

- `vk.ru` - главная страница
- `api.vk.ru` - API сообщений, лайков, комментариев и т.д.
- `media.vk.ru` - внутреннее origin хранилище для CDN
- `login.vk.ru` - авторизация
- `mycdn.me` - CDN для статики, медиафайлов и снапшотов популярных постов

Исходя из таблицы из [ДЗ 2](./02.md#сетевой-трафик), ясно что самый тяжелый
трафик создают изображения и видео из ленты и поиска. API ленты и поиска
возвращает только карточки, тексты, счетчики и ссылки на `cdn_url`, а сами
медиафайлы клиент скачивает с CDN.

Под CDN попадают:

- статика web/mobile-клиентов;
- фотографии, видео, аватары и preview;
- публичные snapshot-объекты популярных постов, если они уже подготовлены как статический JSON.

## Размещение датацентров

Датацентры пытаемся размещать в местах с хорошей городской инфраструктурой,
чтобы обеспечить высокую скорость физического доступа, надежность,
низкую цену за электричество и обслуживание.

Три равных датацентра ставим в Петербурге, Москве и Екатеринбурге.

В датацентрах закладываем избыточность.
Имея 33%+33%+34% инфраструктуры на ~[300к API RPS](./02.md#rps),
То есть каждый датацентр в идеале держит пик примерно на 100к API RPS с запасом.

Берем N+1 redundancy + active-active инфраструктуру на 150к RPS на датацентр.
Мы хотим позволить себе потерять один датацентр и продолжать работу без деградации.

### Балансировка API

Принимаем тот факт, что пользователи с Дальнего Востока пойдут за API в ЕКБ на ~7000 км = 70мс => RTT = 140мс.
Для комментариев и сообщений это не так заметно. Лента и поиск остаются API-запросами,
а медиафайлы из них отдаются через CDN.

Для балансировки API используем ближайший (с точки зрения сети) и здоровый датацентр.
Используем Anycast, подгоним веса BGP так, чтобы трафик распределялся примерно 33%+33%+34%.

## CDN

Ставим CDN в крупных городах для обеспечения быстрой работы по всей России:
Москва, Волгоград, Екатеринбург, Новосибирск, Хабаровск.

На CDN кладем статику, медиафайлы и заранее подготовленные публичные snapshot-объекты популярных постов.
С бекенда пользователю отдаем ссылку на `mycdn.me`, а не `media.vk.ru`.
CDN будет искать у себя кеши, если их нет - идти на `media.vk.ru` за данными.

Это не гарантирует доступность 100% пользователям при падении CDN, но зато просто в реализации
и повышает шансы.

### Балансировка CDN

CDN определяем по Latency-based DNS: ходим туда, где быстрее всего (учитываем health check)
Всегда отдаем пользователю самый быстрый CDN, а также второй по скорости для резервного варианта.
Держим TTL в 1 минуту, чтобы реагировать на падение CDN.
